Dunjin Modding — Detailed Reference

This is the expanded companion to the main modding guide. Where the main guide gives you the shortest path to a working mod, this document goes deep on every field, every validator rule, every API function, and every gotcha — for when you're building something more ambitious than a single relic.

================================================================
1. Setup & File Structure
================================================================

Mods are Steam Workshop items, not manually-uploaded folders. The flow is:

1. Enable mods: Settings -> Advanced -> Enable Mods (this is a stored preference, META.modsEnabled, and takes effect after a restart).
2. Subscribe to a mod on the Steam Workshop.
3. Restart the game. On boot, if mods are enabled, the game calls into a Steam bridge (window.dunjinDesktop.steam.getWorkshopModsSync) to read all subscribed Workshop items.
4. The MODS button on the title screen lets you manage (enable/disable individually) and view errors for loaded mods — it does not accept raw file uploads directly; the files come from the Workshop subscription's synced folder.
5. If mods are enabled but there's no Steam bridge (e.g. a browser build), mod loading is silently skipped — no error, just no mods.

A mod is a folder (synced from Workshop) containing:

- manifest.json — identity only. Fields: id, name, version, author. The id must be lowercase letters and digits only (regex: ^[a-z0-9]+$) and becomes the mod's namespace.
- One or more content JSON files — each containing enemies / relics / potions / heroes arrays (or, for enemies specifically, the file can also just be a bare array). A mod doesn't need all four content types.

Duplicate mod ids are rejected: if two subscribed Workshop items claim the same manifest id, the second one is skipped entirely with a "duplicate mod id" error.

Load order: mods load after the base game's content pools exist and before any save is loaded, since saved runs can reference mod content by id string.

--- Namespacing rules (strict) ---

Every content item's id must:

- Match ^[a-z0-9]+_[a-z0-9_]+$ — lowercase, at least one underscore separating a namespace segment from the rest.
- Start with your mod's manifest id plus an underscore (e.g. mod id bogpack means every item id must start with bogpack_).
- Not collide with any existing base-game relic or potion id, or (for heroes) any existing CLASSES id.

Enemies have an additional constraint beyond id: the display name (n field) must be globally unique against every enemy in the base game and every other loaded mod. This is because the engine keys bestiary tracking, save resolution, and boss-encounter history by display name, not by id — ENEMY_ART[e.n], META.seenEnemies, run.defeatedEnemies, and run.lastBossName all store the name string directly. A duplicate name would silently corrupt another enemy's tracking data.

--- Error handling ---

Bad items are rejected loudly, not silently dropped. Every validator function calls modError(label, message) with a specific, actionable reason (e.g. "bogpack_ward: rarity must be one of common|uncommon|rare|epic|legendary|mythic") rather than just skipping the item with no explanation. Check the mod error log (surfaced via the MODS panel) after every restart — a typo in a field name or an out-of-range value will show up there with the exact reason it failed.

--- ID immutability ---

Once a save file references an item id, that id is permanently baked into that save. Renaming or removing an id after players have used it in a run will corrupt those saves — there is no migration path. Treat published ids as immutable. If an item needs a significant change, ship a new id and leave the old one in place (even as a no-op) rather than renaming.

2. Enemies
================================================================

Enemies are pure data — no hooks, no code.

{"enemies":[{"id":"bogpack_reaver","n":"Swamp Reaver","tier":"grunt","hp":70,"ac":9,"dmg":8,"shield":10,"armor":20,"atk":"poison","effect":"unsteady"}]}

--- Fields & validation ranges ---

- id — see namespacing rules above.
- n — display name, 1-40 chars, globally unique (see above).
- tier — one of grunt, vanguard, elite, boss. Sets the internal vanguard/elite/boss flags, which affect where the enemy can spawn and which unlock/encounter-tracking systems count it.
- hp — 1 to 100,000.
- ac — 0 to 20. This is a hard engine ceiling, not just a validator preference: startCombat() builds the live enemy with ac:Math.min(def.ac+acF,20), and the player's roll is clamped with total:Math.min(20,nat+bonus). An AC above 20 would be unreachable by any roll and therefore meaningless — the validator rejects it rather than let you publish an enemy whose stat block lies about itself.
- dmg — 0 to 1000.
- shield — 0 to 100,000 (optional, defaults 0). Stripped by Arcane damage.
- armor — 0 to 100,000 (optional, defaults 0). Stripped by Shadow damage.
- atk — must be one of the Attack Types list (section 9).
- effect — optional. Must be one of the existing enum keys in BOSS_EFFECTS (the name is historical; despite the name, effects are not boss-exclusive — see below). Custom/novel effect keys are out of scope; only the base game's fixed effect set is available to mods.

--- Effects are available to every tier ---

The engine doesn't gate effects on e.boss — startCombat() reads def.effect unconditionally to seed demandSigil / sourSigil / jammedIds, and every consumer checks combat.enemy.effect==="...", regardless of tier. The bestiary tooltip and the combat ability badge display effects the same way on every tier too, so a modded grunt carrying an effect will correctly announce it to the player in the UI. Base-game enemies only use effects on bosses as a design convention, not because the engine requires it; your mod is free to put unsteady on a grunt.

--- Enemy Effects (full list) ---

- numbed (Trembling Hands) — -2 hand size for the battle.
- vulnerable (Cracked Ward) — you take +25% damage for the battle.
- relicjam (Faulty Toolbelt) — disables 2 random relics every turn.
- unsteady (Shaky Ground) — -2 to all d20 rolls for the battle.
- potionseal (Sealed Satchel) — potions are disabled for the battle.
- sigilsour (Hindrance) — a random sigil is fully nullified each hand (scores no Mana or Mult).
- patternread (Open Book) — your most-played hand type this run is fully nullified.
- weakened (Leaden Arms) — you deal -25% damage for the battle.
- sigilread (Tipped Hand) — your most-played sigil so far this battle is fully nullified.
- noescape (Cornered Rat) — 0 discards for the battle.
- demand (Solemn Order) — a demanded sigil (changes every hand) must be played or you deal 50% less damage.
- courtspurge (Court's Purge) — face cards (J/Q/K) are fully nullified for the battle.

3. Relics
================================================================

Relics come in two flavors: stat-only (pure JSON, no code) and hook-driven (JavaScript logic). Prefer stat-only whenever possible — it's less error-prone and gets Echo Chamber mirroring and Relic Jam suppression for free, since relicSum(key) already walks every relic (mod or base-game) and the Echo Chamber mirror target the same way.

--- 3.1 Stat-Only Relics ---

{"relics":[{"id":"bogpack_ward","name":"Marsh Ward","rarity":"rare","desc":"Take 25% less Poison damage.","resistTypes":["poison"],"resistPct":0.25}]}

A relic needs at least one hook or one recognized stat field — an empty relic is rejected. Every field you attach is validated against a strict numeric range (unknown fields are rejected loudly, not dropped silently — see section 1).

--- 3.2 Full Stat Field Reference (with validated ranges) ---

Hand economy
- chips [-999, 999] — flat Mana added to every hand.
- mult [-99, 99] — flat Mult added to every hand.
- multX [0, 10] — Mult multiplier (applied after flat mult).
- multPerCard [-20, 20] — Mult per card in the played hand.
- combo — grants a bonus when a specific hand type (or "any") is played. Must be a valid HAND_TYPES key. Requires at least one of chips/mult/multX to also be set — a combo relic that grants nothing is rejected.
- handSize [-3, 3], discards [-3, 3], hands [-2, 2] — resource caps for the run.

Per-sigil scoring — fully symmetric across all four schools
Every school has both a Chips (Mana) field and a Mult field:
- Arcane: arcChips [-999, 999], arcMult [-99, 99]
- Divine: divChips [-999, 999], divMult [-99, 99]
- Shadow: shadowChips [-999, 999], shadowMult [-99, 99]
- Martial: marChips [-999, 999], marMult [-99, 99]

Example — Martial equivalent of Sage's Insight, mirroring the Arcane/Divine pattern exactly:

{"relics":[{"id":"bogpack_warcry","name":"War Cry Standard","rarity":"uncommon","desc":"+1 Mult per Martial card scored.","marMult":1}]}

faceChips [-999, 999], faceMult [-99, 99] — per face card (J/Q/K) scored.
oddChips [-999, 999] — per odd-rank card scored (mirrors Shadow Scrawl's pattern).
monkMult [-99, 99] — Mult when 3+ distinct suits are played in one hand.

Armor & combat rolls
- armor [0, 200] — flat armor granted.
- roll [-5, 5] — flat bonus to every d20 roll.
- rollFloor [0, 20] — sets a minimum on rolled results.
- critWiden [0, 5] — lowers the natural roll needed to crit.
- noFumble — flag (true/false); prevents natural 1s from being a full miss.
- rerollOne — flag (true/false); rerolls a natural 1 once (Lucky Charm's mechanic).

Resistances & type interactions
- resistTypes (array of attack types) + resistPct [0, 0.9] — % less damage taken from listed types. Must be declared together — declaring one without the other is rejected.
- vsTypes + vsTypesPct [0, 2] — % more damage dealt to enemies using listed attack types. Same pairing rule.
- vsTier (grunt|vanguard|elite|boss) + vsTierPct [0, 2] — % more damage dealt to a given enemy tier. Same pairing rule.
- hpDmgPct, armorDmgPct, shieldDmgPct — each [-0.9, 2] — % modifiers to damage against each specific enemy resource layer.

Economy & utility
- luckBonus [-0.5, 0.5] — added chance on event, treasure, and camp rolls.
- shopDiscount [0, 0.75] — % off shop prices.
- potionPotency [-0.5, 2] — % stronger potions.
- healAfter [0, 200] — flat HP healed after every battle.
- goldAfter [0, 500] — flat gold gained after every battle.
- healAfterPct [0, 0.5] — % of max HP healed after every battle. (Both healAfter and healAfterPct are legal on relics, despite healAfterPct originally being a hero-only pattern — Cleric uses it on her hero bonus, but the field is in the shared MOD_STAT_FIELDS table so a relic can use it too.)

--- 3.3 Hook-Driven Relics ---

{"relics":[{"id":"bogpack_hoard","name":"Bog Hoard","rarity":"rare","desc":"+1 Mult per 50 gold.","echoCompatKeys":["hoard_mult"],"hooks":{"onScoreHand":"api.addMult(Math.floor(api.run.gold()/50));"}}]}

Allowed hooks on a relic: onScoreHand, onHandResolved, onDamageTaken, onBattleStart, onBattleEnd, onDiscard, onShopEvent, onPickup, onRoll, onNodeEnter. (Note: use is potion-only, not valid on a relic.)

Echo Chamber mirroring is opt-in for hook-driven relics, because a hook can't be introspected the way a stat field can:
- echoIncompatible: true — explicitly blocks mirroring. Use this for state-machine or once-per-run relics where duplication wouldn't make sense.
- echoCompatKeys: ["some_key", ...] — declares that Echo Chamber can mirror this relic, and each key becomes a truthy flag directly on the relic object (which is exactly what the mirroring lookup tests for).
- If you declare neither: a stats-only relic (no hooks, has recognized stat fields) is auto-mirrored for free, since relicSum() and the resist/vs reducers already walk the Echo Chamber target. A hook-driven relic (has hooks) with no explicit declaration defaults to echoIncompatible — silent, un-mirrorable — rather than silently doing nothing when "mirrored." A silent no-op mirror would be worse for players than an obvious omission.

Persistent state: api.state.get(default) / api.state.set(value), auto-namespaced by the item's own id, so two mods (or two relics) can each keep a counter with zero collision risk. Values must be JSON-serializable or the set silently fails (with a logged error) rather than corrupting the save.

================================================================
4. Heroes
================================================================

Heroes combine base run stats with a bonus object, which becomes run.clsBonus internally. Fields in bonus draw from three separate pools:

1. Relic-shared fields (MOD_STAT_FIELDS) — anything from section 3.2 above works identically here, since relicSum(key) already adds run.clsBonus[key] alongside relic totals. This is a deliberate design choice: a hero's bonus takes exactly the same whitelist as a relic's stat fields, no extra engine work required.
2. Hero-only fields (MOD_CLASS_NUM_FIELDS / MOD_CLASS_FLAGS / MOD_CLASS_STR_FIELDS) — read directly off run.clsBonus by hand-written engine checks, and never flow through relicSum(). Declaring one of these on a RELIC would validate cleanly and then silently do nothing (relics never populate run.clsBonus) — which is exactly why they're validated only in validateModClass and kept out of the relic-facing whitelist entirely.
3. Hero-only array fields (MOD_CLASS_ARR_STR_FIELDS) — the same non-flow-through-relicSum() rule as above, just validated as a list of enum strings instead of a single number, flag, or string. Currently one field lives here: relicSpawnGate (see 4.3).

{"heroes":[{"id":"bogpack_ranger","name":"Bog Ranger","rarity":"rare","desc":"Marsh hero.","blurb":"Patient tracker.","perks":"100 HP · +1 hand size · +1 Mult per Arcane card scored","hp":100,"gold":25,"color":"#7cbf57","bonus":{"handSize":1,"arcMult":1},"relics":["oath"],"potions":["heal"]}]}

--- 4.1 Base Fields & Validation ---

- hp — 1 to 500.
- gold — 0 to 500 (optional, defaults 0).
- blurb — required, max 200 chars.
- perks — required, max 300 chars. This is the bullet-style summary on hero-select; nothing auto-generates it from bonus, so keep it manually in sync.
- color — hex value like #9fd0ff (defaults to #cdb47e if omitted).
- relics, potions — arrays of starting item ids, max 3 entries each. Must be base-game ids or ids belonging to this same mod — a hero cannot depend on another mod's content being installed.
- cost — optional. If set (0 to 9999), the hero is coin-purchasable instead of free-from-start; unlockDesc defaults to "Purchase for N coins" if not supplied (max 120 chars).
- Mod heroes cannot use unlockReq (a JS predicate function) the way base-game heroes can — hooks are strings/sandboxed, and a predicate over the player's META save data would need a second sandbox entirely. Mod heroes are therefore either free-from-start or cost-gated; there's no "beat this boss to unlock" path available to mods.

--- 4.2 Hero-Only Numeric Fields (MOD_CLASS_NUM_FIELDS, with ranges) ---

Every hero-only mechanic in the base game — including roll behavior, crit multipliers, and damage-shape effects — has a field here that any custom hero can set. None of these are tied to a specific hero id; setting duelistCritX on a hero you invent works exactly the same as it does on Duelist.

- startShield [0, 100] — flat starting shield, and also raises the run's max-shield tracking (relevant to Warden-style "healing restores shield" builds).
- knightArmor [0, 50] — flat starting shield (Knight's field; functionally similar to startShield but does not touch max-shield tracking).
- faceMultX [0, 3] — Mult multiplier per face card scored.
- allOddMult [-10, 10] — bonus Mult if every card in the hand is odd-ranked.
- allEvenMultX [0, 5] — Mult multiplier if every card in the hand is even-ranked.
- arcSuitMul [0, 5] / arcSuitMonoMul [0, 5] — Mult multiplier when the hand's dominant perk suit is Arcane; the Mono variant applies when the hand is Arcane-only.
- divSuitMul [0, 5] / divSuitMonoMul [0, 5] — same pattern for Divine.
- bruteMartialMul [0, 5] / bruteMartialMonoMul [0, 5] — same pattern for Martial (Brute's signature field, but usable by any hero).
- necroShadowMul [0, 5] / necroShadowMonoMul [0, 5] — same pattern for Shadow (Necromancer's signature field, but usable by any hero).
- bruteRageX [0, 1] — Mult multiplier per hit taken this battle, stacking as the fight goes on.
- maxPotions [-3, 6], maxRelicsBonus [-3, 6] — capacity adjustments.
- critLow [2, 20] — crit threshold; lower it to widen the crit window (default trigger is a natural 20).
- glancePct [0, 1] — damage % dealt on a glancing blow (base default is 0.5).
- bardLuck [-0.5, 0.5] — added chance on event/treasure/camp rolls; stacks additively with the relic field luckBonus.
- rangerNoMartialMul [0, 5] — Mult multiplier when the hand contains no Martial cards. Both scoring paths (the live hand preview and the actual resolution) key off this field's presence, so any custom hero can take it.
- goldPerWin [0, 50] — flat gold per battle won.
- ratkingRelicMult [0, 2] — Mult per relic held.
- duelistCritX [1, 5] — crit damage multiplier, replacing the default 2x. Duelist sets this to 2.5; any hero can now use a different value.
- necroGlanceMult [0, 20] — Mult granted on the hand following a glancing blow. Duelist and Necromancer both key certain other mechanics off "did I just glance," but this specific bonus-mult payout is what Necromancer's bonus sets to 3.
- tankEliteMulX [0, 5] — Mult multiplier applied when you attack a Vanguard or Elite enemy, and also the multiplier applied to your own outgoing damage on a one-shot kill against one. Tank sets this to 1.25.
- tankGruntDmgMulX [0, 5] — multiplier applied to incoming damage from Grunt-tier enemies specifically (bosses, vanguards, and elites are unaffected). Tank sets this to 1.25 as its downside.
- craftsmanRelicBoost [0, 1] — added chance weight toward relic drops from events/treasure/camp, and it also feeds the rarity-weighting roll used whenever a relic is picked (so a higher value skews rewards toward rarer relics too, not just more frequent ones). Craftsman sets this to 0.15.
- craftsmanOneShotChance [0, 1] — chance of an extra bonus relic when your first hand of a battle kills a full-HP enemy outright. Craftsman sets this to 0.5.
- fatespinnerCritRollGain [0, 5] — how much the natural-roll floor permanently increases per crit landed, up to the existing +5 cap. Fatespinner sets this to 1.
- wardenArmorMultDivisor [1, 100] — pairs with the wardenArmorMult flag below. Changes the shield-per-Mult divisor that flag applies; default 25 (i.e. +1 Mult per 25 shield held) if omitted. A hero with wardenArmorMult:true, wardenArmorMultDivisor:10 gets +1 Mult per 10 shield instead. Has no effect unless wardenArmorMult is also set true — the engine only reads this divisor from inside that flag's check.
- graveBurialDivisor [1, 52] — pairs with the graveBurial flag below. Changes the missing-card divisor for that flag's Mult bonus; default 2 (i.e. +1 Mult per 2 cards below a full 52-card deck) if omitted. Does not change graveBurial's other effect (the weakest unenchanted card being removed after every battle) — that stays fixed regardless of this field. Has no effect without graveBurial also set true.
- monkMultXFactor [1, 5] — pairs with the monkMultX flag below. The multiplier applied when the played hand has exactly 3 distinct suits; default 1.5 if omitted.
- monkMultXFactor4 [1, 5] — pairs with the monkMultX flag below. The multiplier applied when the played hand has 4+ distinct suits; default 2 if omitted. Set independently of monkMultXFactor — a hero can flatten the curve by setting both fields equal, or exaggerate it by spreading them further apart. Neither field does anything without monkMultX also set true.
- rangerMultXFactor [1, 5] — pairs with the rangerMultX flag below. The multiplier applied on High Card/Pair hands; default 2 if omitted. Has no effect without rangerMultX also set true.

--- 4.3 Hero-Only Flags (MOD_CLASS_FLAGS, true/false only) ---

- wardenHeal — all healing also restores shield instead of just HP.
- wardenArmorMult — +1 Mult per 25 shield currently held. The 25 is adjustable via wardenArmorMultDivisor above.
- monkMultX — doubles (or 1.5x/2x depending on suit count) the monkMult bonus instead of adding it flatly. Both multipliers are adjustable via monkMultXFactor / monkMultXFactor4 above.
- graveBurial — the weakest unenchanted card is removed from the deck after every battle; +1 Mult per 2 cards missing from a full 52-card deck. (Gravekeeper's mechanic.) The card-divisor is adjustable via graveBurialDivisor above; the card-removal side effect is not adjustable.
- twinSchoolDeck — the 52-card deck is restricted to two randomly-chosen schools at run start. (Twinsoul's mechanic.)
- randomDeck — the 52-card deck is entirely randomized (any school, any rank, duplicates allowed). (Lottery Saint's mechanic.)
- rangerMultX — doubles Mult on High Card/Pair hands. Same as rangerNoMartialMul above: usable by any hero, not gated to a specific id. The multiplier is adjustable via rangerMultXFactor above.
- noDiscards — converts what would be discards into extra attacks instead (Bombardier's mechanic).
- duelistGlanceFumble — a natural 1 becomes a glancing blow instead of a fumble. Duelist sets this true.
- necroRebornCrit — a natural 1 is instead treated as a natural 20 (a crit). Necromancer sets this true. Note this stacks oddly with duelistGlanceFumble if a hero somehow had both set — the nat-1 rewrite checks run in a fixed order, so test any hero that combines roll-altering flags.
- ratkingCommonOnly — every relic offered, sold, or found while this hero is active is restricted to common rarity. Ratking sets this true. This predates, and is narrower than, the relicSpawnGate array field below — relicSpawnGate can express the same restriction (["common"]) plus any other rarity subset, so new mod heroes should generally prefer it; ratkingCommonOnly remains available (and is what Ratking's own save data still relies on) purely for backward compatibility.
- fatespinnerRollDmg — multiplies all damage dealt by (natural roll ÷ 10), so a natural 20 deals double and a natural 4 deals well under normal. Fatespinner sets this true; pair carefully with anything that also floors or rerolls the natural die, since a rigged roll interacts directly with this multiplier.
- startRandomCommonRelic — grants one random common-rarity relic at run start, chosen independently of relicSpawnGate (see below) — this one-time grant bypasses the normal spawn-pool gate entirely.

--- 4.4 Hero-Only Array Field (MOD_CLASS_ARR_STR_FIELDS) ---

- relicSpawnGate (array of rarity strings, e.g. ["epic","legendary"]) — restricts which relic rarities this hero can find, from every source that draws from the relic pool (shop, event rewards, treasure, camp). relicSpawnable() is the single choke point every relic-grant path calls through, so declaring this field covers all of them automatically — you don't need to gate each source separately.
  - Must be a non-empty array; each entry must be one of the six valid rarities (common|uncommon|rare|epic|legendary|mythic), validated the same way as potionPotencyMaxRarity below, just against a list instead of a single value. Unrecognized entries are rejected loudly; duplicate entries are silently deduped.
  - Does not affect relics granted outside the normal spawn pool — startRandomCommonRelic above and Ratking's tribute-event relic grant both bypass relicSpawnable() and hand out a specifically common relic directly, regardless of what this field says.

--- 4.5 Hero-Only String Field (MOD_CLASS_STR_FIELDS) ---

- potionPotencyMaxRarity (one of common|uncommon|rare|epic|legendary|mythic) — caps which potion rarities benefit from this hero's potionPotency bonus; any potion above the given rarity gets none of that bonus. Alchemist sets this to "rare" alongside a high potionPotency value, so cheap potions get boosted hard while a lucky Legendary find isn't over-tuned.
